## Fitness Schedule — Расписание фитнес-классов
Учебный проект, разработанный в рамках практической работы № 3 по дисциплине «Тестирование программного обеспечения».
Вариант: 75 Тема: Расписание фитнес-классов Язык программирования: Python 3.11+
Описание проекта
Fitness Schedule — это учебная система для управления расписанием фитнес-классов. Она позволяет создавать занятия, изменять их параметры, регистрировать участников и отменять занятия.
Основное внимание в проекте уделено применению подходов к разработке и тестированию программного обеспечения: TDD, ATDD, BDD и SDD.
Функциональные возможности
* Создание фитнес-классов с указанием названия, даты, времени и вместимости.
* Изменение параметров существующих занятий.
* Просмотр списка занятий с сортировкой по дате и времени.
* Регистрация участников на занятия.
* Проверка доступности свободных мест.
* Предотвращение повторной регистрации одного участника.
* Отмена занятий.
* Проверка корректности входных данных.
* Автоматическое тестирование основных сценариев работы системы.

Назначение основных файлов
* models.py — модели данных фитнес-класса и его статуса.
* service.py — бизнес-логика создания, изменения, отмены занятий и регистрации участников.
* test_tdd.py — тесты создания и изменения расписания, включая проверку некорректных данных.
* test_atdd.py — тесты пользовательских требований к регистрации участников.

Подходы к тестированию
1. TDD — Test-Driven Development
Разработка через тестирование. Тесты используются для определения ожидаемого поведения функций создания и изменения расписания.
Проверяются:
* успешное создание занятия;
* отклонение пустого названия;
* проверка допустимой вместимости;
* изменение времени занятия;
* запрет уменьшения вместимости ниже количества зарегистрированных участников.
2. ATDD — Acceptance Test-Driven Development
Разработка на основе приёмочных тестов. Проверяется соответствие системы требованиям пользователя.
Основные сценарии:
* успешная регистрация участника;
* отказ при отсутствии свободных мест;
* отказ при повторной регистрации;
* запрет регистрации на отменённое занятие.
3. BDD — Behavior-Driven Development
Разработка через описание поведения системы. Сценарии записаны на языке Gherkin и выполняются с помощью Behave.
Пример сценария:
Feature: Регистрация на фитнес-класс

  Scenario: Успешная регистрация участника
    Given фитнес-класс запланирован
    And в классе есть свободные места
    When участник регистрируется на класс
    Then участник отображается в списке
4. SDD — Specification-Driven Development
Разработка на основе спецификаций. Для проверки используются таблицы входных данных, ожидаемых результатов и параметризованные тесты.
Тестируются допустимые и недопустимые комбинации параметров занятия и регистрации участников.

Для работы с проектом необходимы:
* macOS, Windows или Linux;
* Python версии 3.11 или выше;
* pip для установки зависимостей.
Проект совместим с MacBook на Apple Silicon (M1). Отдельная настройка архитектуры процессора не требуется при использовании подходящей версии Python для macOS.
Установка и запуск
1. Клонирование репозитория
git clone <URL-ВАШЕГО-РЕПОЗИТОРИЯ>
cd fitness-schedule
Замените <URL-ВАШЕГО-РЕПОЗИТОРИЯ> на ссылку своего GitHub-репозитория.
2. Создание виртуального окружения
python3 -m venv .venv
3. Активация виртуального окружения
source .venv/bin/activate
4. Установка зависимостей
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
5. Запуск автоматических тестов pytest
python -m pytest -v
Команда запускает тесты из каталога tests/ и отображает результаты выполнения.
6. Запуск BDD-сценариев
python -m behave
Команда запускает сценарии из каталога features/ и показывает, какие сценарии пройдены.
Ожидаемые результаты тестирования
При корректной настройке окружения ожидается выполнение:
* 5 проверок TDD;
* 4 проверок ATDD;
* 6 проверок SDD;
* 2 BDD-сценариев.
Таким образом, предусмотрено 15 проверок pytest и 2 BDD-сценария. Фактический результат необходимо подтвердить запуском команд в локальном окружении.
Ограничения проекта
Проект является учебной реализацией и имеет следующие ограничения:
* данные хранятся в оперативной памяти и не сохраняются после завершения программы;
* графический интерфейс отсутствует;
* авторизация пользователей не реализована;
* участники идентифицируются по имени;
* интеграция с внешними сервисами и базой данных отсутствует.
Для дальнейшего развития можно добавить постоянное хранение данных, уникальные идентификаторы пользователей, REST API, пользовательский интерфейс и интеграционные тесты.
Результат работы
В рамках проекта реализована базовая бизнес-логика управления расписанием фитнес-классов и подготовлен набор автоматизированных тестов, демонстрирующих применение TDD, ATDD, BDD и SDD.
Проект предназначен для изучения организации тестирования программного обеспечения и проверки требований на примере небольшой предметной области.
